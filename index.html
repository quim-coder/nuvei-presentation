The Problem

1 Incomplete Data
New accounts arrive without sufficient information to act on.
•Incomplete decision-maker contact information
•Limited context about company pain points and business needs
•Raw data without actionable intelligence synthesis
2 Inefficient Assignment
No data-driven way to identify the optimal AE for each account.
•Random assignments without strategic criteria
•Suboptimal matching between accounts and AE strengths
•Unnecessary reprocessing of duplicate accounts
Impact: Without enriched data + intelligent assignment + deduplication → missed opportunities, lower close rates, wasted resources.

2. Multi-Layer Enrichment + AI
Five parallel data sources + Claude AI synthesis = complete Enrichment Card. Converts raw data into actionable business intelligence.
3. Data-Driven Matching
Gong-based AE profiles + weighted scoring algorithm = optimal seller assignment. Includes continuous learning feedback loop.

STEP -1: Intelligent Deduplication

Identify Duplicate Accounts Before Processing

•Crunchbase ID (alternative verification)
⚙️Actions by Result

SKIP enrichment. Cost: $0
If: Data is stale (30-90 days)
REFRESH signals only. Cost: $0.30
If: Completely new account
CONTINUE to full enrichment workflow
Purpose: Prevents unnecessary reprocessing, maintains data integrity, and optimizes resource spending.

STEP 0: Validation Gate & STEPS 1-5: Enrichment

STEP -1: Deduplication
Checks if account ALREADY EXISTS in our system
Question: "Is this a record we've seen before?"
Data source: Database lookup (domain, LinkedIn ID, parent company, Crunchbase ID)
Purpose: Avoid re-processing duplicates and save costs
Result: If match found → SKIP or REFRESH | If no match → Continue to Step 0
STEP 0: Pre-Validation Gate
Checks if NEW account meets minimum criteria for enrichment
Checks (automated):
✓ Valid domain populated? | ✓ ICP match? | ✓ Not enriched in last 90 days? | ✓ SDR assigned?

Result: If ALL checks pass → CONTINUE to enrichment
Result: If ANY fails → EXIT (log reason, cost $0)
⚡ STEPS 1-5: Five Parallel Enrichment Layers
These layers execute SIMULTANEOUSLY, not sequentially

Layer 1 - Clay APIs: ZoomInfo → Apollo → Hunter | Output: Company data, emails, phone numbers | Cost: $0.20 | Time: 5 min
Layer 2 - Claygent AI: Web scraping (/about, /careers, LinkedIn, Glassdoor) | Output: Culture signals, hiring activity, funding news | Cost: $0.50 | Time: 10 min
Layer 3 - Market Signals: Crunchbase, LinkedIn Jobs, BuiltWith, News | Output: Funding rounds, tech stack, hiring trends | Cost: $0.30
Layer 4 - Internal Context: Salesforce query (similar customers) | Output: Deal benchmarks, win/loss patterns, ICP alignment | Cost: FREE
Layer 5 - Phone Enrichment: Hunter → Apollo → RocketReach | Output: Mobile/office phones, decision-maker direct lines | Cost: $0.30 | Time: 3 min

From Raw Data to Actionable Intelligence

Claude API Synthesizes All Data Into Intelligence

Deep Dive: Intelligent Seller Matching Algorithm

How AE Profiles Are Built
Data Source: Gong call recordings (historical performance)
Analysis: Vertical expertise, buyer personas handled, deal sizes closed, win rates, objection handling
Output: Individual AE profile database (one profile per sales rep)
Weighted Scoring Formula
Each AE scored across six dimensions (weights shown):

• Vertical Specialty (30%): Expertise in the account's industry
• Buyer Persona Alignment (20%): Track record with this type of decision-maker
• Deal Size Capability (15%): Experience with similar deal values
• Current Capacity (15%): Available bandwidth and workload
• Quota Momentum (10%): Performance against current targets
• Development Potential (10%): Coachability and growth trajectory

Result: Composite score 0-10 per AE
Matching Process & Output
Input: Enrichment Card (account intelligence) + 60 AE profiles
Algorithm: Score each AE against account characteristics
Rank: Sort all 60 AEs by score (highest to lowest)
Output: Top 3 ranked recommendations with detailed rationale
Rotation Logic: Apply workload balancing to ensure fair distribution
Why this works: Algorithm is data-driven (Gong history) rather than subjective. Weights reflect business priorities. Continuous feedback loop (Gong results) refines scoring monthly.

Scalability: Growing from 1,000 to 100,000+ Accounts

Infrastructure: AWS Lambda (Serverless)
1,000 accounts split into batches (50 each) → Lambda functions spawn CONCURRENTLY → Each processes all enrichment steps in parallel → All finish at same time → 1,000 accounts enriched in ~20 minutes
Cost Efficiency
At 1,000 accounts/month: Variable costs per account + fixed infrastructure

At 10,000 accounts/month: Same variable costs per account, but fixed costs spread across larger volume

At 100,000+ accounts/month: Volume discounts with vendors + fixed costs amortized

Basis: Serverless architecture scales horizontally without re-architecture. Fixed costs are one-time setup.
Processing & Quality
Processing Time:
1k, 10k, or 100k accounts → ~20 minutes (linear scaling via parallelization)

Quality Maintained: Enrichment quality slightly decreases with volume (acceptable trade-off) but stays actionable

Maintained via: Sampling validation (10% random audit), automated quality alerts, monthly feedback loop
Key Insight: System does NOT require re-architecture to grow 10x or 100x. Same code, more Lambda functions. Cost per account may actually decrease due to economies of scale.
